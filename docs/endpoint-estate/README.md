# Unified endpoint estate workbook

`DGO_Unified_Endpoint_Estate_Merged.xlsx` merges four separately-produced workbooks
into one file, adds a reconciliation of the identity claims they disagree on, and
carries the tooling that rebuilds and re-verifies it.

## Sources

| Source workbook | Sheets | Prefix in merged file |
| --- | --- | --- |
| DGO_Endpoint_Estate_Master_Reference.xlsx | 19 | none — original names kept |
| DGO_Flow_Harvest_Collector.xlsx | 10 | `HC ` |
| ECM_Simplified_Forensic_Audit.xlsx | 6 | `FA ` |
| FlowIds_Endpoint_Database.xlsx | 1 | `FI ` |

The four source workbooks are **not committed**: the Harvest Collector carries a live
signed trigger URL (see Redaction). Point `ESTATE_SOURCE_DIR` at a local copy to rebuild.

Master Reference sheets keep their original names because its cover sheet computes 15
live counts with cross-sheet formulas (`'03 Flows'`, `'15 Action Register'`, …). Prefixing
them would break every one.

Sheets are kept whole and side by side rather than concatenated row-wise. The four files
share only the 59 flow IDs; their column sets are disjoint, so row-merging would force
blanks into most columns and destroy the named tables.

## What is in the merged file

- `00 Merge Index` — source file, SHA-256, original sheet name, merged sheet name, rows,
  columns, populated cells, named tables, and the redaction note.
- 36 source sheets, unchanged.
- `20 Reconciliation` — derived. One row per distinct flow ID (59), 33 columns.

Verified on build: 102,905 cells identical to source, 4 intentionally redacted, every sheet
matching its source row x column dimensions, 15 formulas preserved as formulas, 10 named
tables preserved with matching refs.

## Reconciliation

The three flow-bearing sheets cover the same 59 flow IDs; none holds a flow the others
lack. Their workflow IDs disagree on 7 flows. Provenance settles it rather than a majority:

- `03 Flows` has `Workflow ID in package = FALSE` on all 60 rows. Every value there is a
  lookup from an endpoint register, keyed by **endpoint key**. One value is spread across 6
  flows (GET_DOCS) and another across 3 (REFERENCE_DATA), so at most one flow per key can
  own it.
- `FI FlowIds Database` reads the maker portal **per flow**.
- `FA Record Exceptions` carries 43 records with 0 Power Automate Flow IDs, keyed by
  endpoint key as well — so it corroborates the key, not the flow. On the single flow where
  it does carry a per-flow value (`IP_Create_Task`), it matches FlowIds.

Outcome across 59 flows: 25 master-not-declared, 15 with no workflow ID in any source,
10 agree, 7 conflicts resolved to the FlowIds value, 2 endpoint-key value only.

The sheet also collapses the Harvest Collector's two runs to the latest per flow, lists the
8 flows carrying more than one display name, maps 36 flows to endpoint keys, and joins 26
flows to an audit record.

## Redaction

A signed Power Automate URL is a bearer credential: possession alone authorises invoking the
flow. So is an API key. The Master Reference redacts its own; the Harvest Collector's raw
error payloads redact nothing, and they carried **five distinct credentials** across eleven
cells of `HC 08 Errors`:

| Credential | Cells | Now reads |
| --- | --- | --- |
| Power Automate SAS signature | G9, G12, G69, G72 | `sig=REDACTED` |
| OpenAI API key | G61, G121 | `sk-REDACTED` |
| OpenRouter API key | G37, G97 | `sk-or-v1-REDACTED` |
| HuggingFace token | G39, G99 | `hf_REDACTED` |
| Google API key | G21, G54, G81, G114 | `AIza…REDACTED` |

Each prefix survives so a reader can still tell what was there.

**All five are live at their source until rotated.** Removing a credential from a file
revokes nothing — only regenerating it at the issuer does.

`tools/redact.py` first matched `sig=` alone, which is how the four API keys reached a pushed
commit before a wider sweep caught them. It now matches by credential *shape* — OpenAI,
Anthropic, OpenRouter, HuggingFace, GitHub, Slack, AWS, Google, JWT, SAS signature and
connection-string secrets — and refuses to exit successfully if anything survives its own
pass.

## External references removed

The source workbooks were generated by tooling that lives in another project and recorded
that project's build provenance: an originating repository and branch, a build commit, and
the paths of the export and verify scripts. Those identifiers mean something where they
were written and nothing here, so `tools/scrub_external_refs.py` removes them. 135 cells
changed, all of them provenance: the cover sheet's build rows, `03 Flows` columns L and M,
the register-source columns, the collector README's generator rows, and four sentences that
pointed at the originating repository as a place.

Foreign artifact names go with it: the exported package names in `03 Flows` column M, the
export tooling in column L, the verify scripts named in prose, and the register files the
workflow IDs were looked up in (`02 Endpoint Register` columns N and X, and the same values
carried into `20 Reconciliation`). The register's endpoint key survives in brackets, because
the key is estate data and load-bearing for the reconciliation basis: `endpoint register
(GET_DOCS)`.

`03 Flows` keeps `Package bytes` and `Package SHA-256` beside the removed package name. The
row is still identified by its Capture ID and Flow ID, so the hash describes the package
that row came from without naming a file.

File names the estate itself owns are **not** touched. `workflowdefinition.json` is the
platform's own schema name; `hybrid-assign.schema.json` and the rest in `06 Request Schemas`
are values inside the flows' contracts; and the 39 `__full_definition.json` occurrences in
`15 Action Register` and `HC 08 Errors` sit inside flow expressions such as
`@{workflow()?['run']?['name']}__full_definition.json`, which is a name a flow builds at run
time to write into SharePoint. Those are data, not provenance.

This costs the workbook something, and it is worth stating plainly: an audit-grade document
that can no longer name the commit it was built from can no longer prove which export it
came from. That trace now lives only in the originating project.

## Rebuilding

Each tool finds the workbook next to itself, so `ESTATE_WORKBOOK` is only needed to point at
a different file. `ESTATE_SOURCE_DIR` is required by the stages that read the sources.

```sh
export ESTATE_SOURCE_DIR=/path/to/the/four/source/workbooks

python3 tools/merge.py          # merge all four, losing nothing
python3 tools/verify.py         # read back and assert nothing was dropped or altered
python3 tools/reconcile.py      # add 20 Reconciliation
python3 tools/redact.py         # strip live signatures before committing
python3 tools/scrub_external_refs.py   # erase references to any other repo, branch or commit
```

Every stage edits `ESTATE_WORKBOOK` in place, so the five commands above run in order and
leave one file behind.

`tools/audit_columns.py` re-audits every sheet and column against source; `tools/dupes.py`
reports duplication and cross-source disagreement. Requires `openpyxl`.

Run after a scrub, `audit_columns.py` reports exactly one mismatch — `01 Cover`, where the
build-provenance row was rewritten on purpose — and reports `col diff: set()` for it,
meaning no column moved. Any other mismatch is a defect.

## Reproducibility

Rerunning the five commands from the original sources reproduces the committed workbook
exactly, with one cell different: `00 Merge Index!A4`, the build timestamp.
